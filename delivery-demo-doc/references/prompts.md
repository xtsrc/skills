# 提示词库（按执行链路逐段使用）

占位符统一格式：`{系统名}` `{代码库路径}` `{知识库路径}` `{标书路径}` `{测试环境}` `{测试账号}` `{业务对象}`。

## P1 事实收集

```
从 {代码库路径} 与 {知识库路径} 收集 {系统名} 交付演示文档所需事实，输出素材清单：
1. 渠道/入口：对象从哪里进入系统（每渠道的接入方式、身份识别、建单方式）
2. 角色与机构：谁参与处理，各自职责与权限边界
3. 对象生命周期：全部状态（含界面本地化名）、状态迁移条件
4. 界面动词：真实菜单/按钮名（界面语言原文 + 中文释义）、可见条件
5. 关键参数：SLA/时限/窗口期/阈值/日历（以现网配置为准）
6. 分支与回退：兜底、挂起、升级、特殊件、打回/重开等
7. 审计与通知：哪些动作留痕、哪些事件通知
8. 标书/需求书相关章节要点（仅作对照，不预设已实现）
每项注明来源文件路径；不确定的标"待核实"，禁止推测。
```

## P2 事实校准

```
对照 {代码库路径} 与 {知识库路径} 校准以下易错项，输出"已实现/规划中"两张表：
- 时限类参数（首响/更新/解决/预警比例/窗口期）是否为现网值而非早期设计稿
- 状态机与状态界面显示名是否与现网一致
- 机制启停（如自动升级/自动关闭/转移开关）当前实际行为
- 按钮可见条件与收窄规则
- 标书要求但系统未实现的功能 → 一律移入"规划中"，不得写成已有功能
结论只允许来自代码、知识库或测试环境实测。
```

## P3 主线建模

```
为 {系统名} 的 {业务对象} 建模一条从生到死的闭环主线：
1. 用一句话写出主线（起点→…→终点→可能的回路）
2. 拆成 6-10 个可演示站点，每站：中文名 + 界面语言名 + 谁在场 + 发生什么
3. 标出所有回路（谁在什么条件下把对象拉回哪一站）
4. 为每站定义"闭环去向"（下一站，或进入哪条支线）
输出：站点列表 + 回路列表，作为交互看板的站点条。
```

## P4 支线梳理

```
梳理主线之外的支线，每条固定四段：
触发（什么条件下进入支线）→ 操作（界面按钮与规则）→ 系统（自动做什么、留什么审计）→ 回到（主线哪一站继续）
必查支线类型：路由/分配兜底、挂起等待、升级通道、超时自动处理、特殊件（如敏感）、全部回退（打回/撤回/重开/外部来信）。
每条支线末尾必须写明"回到主线第 X 站"。
```

## P5 站点内容生成（每站四块）

```
为站点 {N：站点名} 生成四块内容：
① 界面操作：编号步骤，写清在 {测试环境} 打开哪里、点什么按钮（界面语言原文）、填什么、预期看到什么
② 系统在做什么：该环节系统自动执行的行为、规则、留痕（面向使用者，不写代码路径）
③ 名词与功能：本环节出现的 2-3 个术语，每个一句话讲清
④ 常见问题：2 个使用方真实疑问，格式"常见问题：…"，答案面向使用者自救
末尾加"闭环去向"一行。角色代入卡用"现在你是：{角色}"，不出现讲解人。
```

## P6 场景设计

```
先按业务内容分类（如咨询类/查询类/办理类/反馈类），讲清"内容决定路径"；再为每类设计一个场景，固定六要素：
场景（一句话故事）→ 角色（谁参与）→ 步骤（走主线哪些站/支线）→ 结果（对象到什么状态）→ 下一步（谁接手或如何回路）→ 闭环点（这一场景证明了什么闭环）
至少一个场景完整走完主线终点；一个场景走升级/超时支线；一个场景走回退回路。
```

## P7 功能卡与角色速查

```
功能卡（F01…Fn）：每张三段——
① 功能定义（一句话：系统实现了什么）
② 使用场景（谁在什么情况下用）
③ 功能确认（可观察的系统行为效果，不写"现场/观察/演示"）
每卡标注对应主线站点/支线；末尾输出功能确认清单表（☐｜功能｜确认方式｜对应位置）。
角色速查（每角色一页签）：每天怎么开始 / 高频按钮 / 不能做的事 / 常见问题。
```

## P8 措辞修订

```
对全文执行措辞审计，逐项替换：
- "坐席问/主管问/居民问/XX问：" → "常见问题："
- "演示者/演示技巧/演示节奏" → 删除或改为"操作说明/阅读建议"
- "现场演示/现场操作" → "在测试环境操作/体验"
- "验收要点" → "功能确认"
- "甲方会怎么问" → "使用中的真实疑问"
- "演示账号" → "测试账号"
- "收尾三问" → "要点回顾"
替换后全文检索：演示、问：、验收要点 应为 0；"现场"仅允许出现在业务名词（如现场代录）。
```

## P9 构建自检

```
交付前自检（逐项输出结论）：
1. 闭环：每条支线/回退是否写明回到主线哪一环
2. 界面：每个操作是否有真实按钮名与预期表现
3. 事实：参数与现网一致；无未实现功能写成已有
4. 措辞：红线词检索为 0
5. 完整：功能清单是否覆盖全部次要功能
6. 交互：站点导航/角色页签/状态跟踪是否可用；打印是否全部展开
7. 文件：标签平衡（div/table/section）、锚点可达、单文件无外部依赖
```
