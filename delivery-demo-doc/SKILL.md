# 交付演示文档生成（Delivery Demo Doc）

为业务系统（工单、客诉、生产、发证、仓储等）生成专业交付演示文档。听众是真实使用方（坐席、业务岗、管理层）与甲方功能验收人员；产出既能讲解又能自学、可逐项确认功能的文档。

## 产出形态

- 默认：单文件交互 HTML——站点导航、状态跟踪器、角色页签、折叠问答；打印自动展开为讲义。骨架见 `assets/demo-doc-template.html`。
- 备选：Word / Markdown（甲方指定格式时），章节骨架与措辞规则不变。

## 执行链路（十步）

详细提示词见 `references/prompts.md`，章节骨架见 `references/doc-skeleton.md`。

| 步骤 | 做什么 | 关键产出 |
|---|---|---|
| 1 事实收集 | 读代码库需求/设计文档、知识库、测试环境界面、标书相关章节 | 素材清单（渠道/角色/状态/按钮/参数/审计） |
| 2 事实校准 | 参数与机制以现网为准，标书只作对照不照抄 | 已实现/规划中两张表 |
| 3 主线建模 | 核心对象生命周期 + 所有回路 | 闭环流程图与站点列表 |
| 4 支线梳理 | 兜底/挂起/升级/特殊件/回退 | 每条"触发→操作→回到主线哪一环" |
| 5 界面绑定 | 每环节写真实菜单/按钮名（含本地化词）与预期表现 | 站点四块内容 |
| 6 场景设计 | 按业务内容分类设计场景 | 场景表（固定六要素） |
| 7 功能清单 | 功能卡 F01…Fn + 功能确认清单 | 功能地图 |
| 8 角色速查 | 每角色入口/高频按钮/不能做/常见问题 | 角色页签 |
| 9 措辞审计 | 按红线词表逐项替换 | 无讲解人视角的定稿 |
| 10 构建自检 | 完整性/闭环/事实/措辞四项检查 | 交付文件 |

## 核心原则（七条）

1. **主线组织**：文档按业务对象流转主线推进（如工单：接入→建单→路由→受理→办结→复核→关闭→评价→重开），不按功能模块罗列，不设名词章。
2. **闭环**：每条支线必须写明回到主线哪一环；回退（打回/重开/撤回）是回路不是终点。
3. **名词嵌入**：术语在出现的环节一句话讲清，不集中解释。
4. **界面对应**：业务流程的每个动作对应测试环境真实按钮/菜单位置与预期表现；按钮名用系统界面语言（如法语）加中文释义。
5. **主次分明但完整**：主流程重点讲；次要功能一笔带过但必须出现（面面俱到），并进功能清单。
6. **现网事实**：SLA 数值、状态名、机制启停、按钮可见条件以代码/知识库/测试环境为准；标书要求未实现的一律不写成已有功能。
7. **使用方与验收方措辞**：全文写给坐席/业务岗/验收人员看，禁止出现对讲解人的提示。

## 措辞红线（定稿前逐项替换）

| 禁用 | 替换为 |
|---|---|
| 坐席问 / 主管问 / 居民问 / XX问： | 常见问题： |
| 演示者 / 演示技巧 / 演示节奏 | 删除，或改为操作说明 / 阅读建议 |
| 现场演示 / 现场操作 | 在测试环境操作 / 体验 |
| 验收要点 | 功能确认 |
| 甲方会怎么问 | 使用中的真实疑问 |
| 演示账号 | 测试账号 |
| 收尾三问 | 要点回顾 |

"现场"仅允许出现在业务名词中（如"现场代录"渠道）。

## 质检清单（发布前）

- [ ] 闭环：每条支线、每个回退都标明回到主线哪一环
- [ ] 界面：每个操作步骤有真实按钮名与预期表现
- [ ] 事实：参数、状态、机制与现网一致；无标书未实现项写成已有功能
- [ ] 措辞：红线词表检索为 0（业务名词除外）
- [ ] 完整：次要功能虽简略但全部出现在功能清单
- [ ] 交互：站点导航、角色页签、状态跟踪可用；打印时全部展开
- [ ] 文件：单 HTML 无外部依赖，标签平衡，锚点可达
